# Book-to-capability and validation map

Source: Sebastian Risi, Yujin Tang, David Ha and Risto Miikkulainen, *Neuroevolution: Harnessing Creativity in AI Agent Design*, user-supplied PDF. Page numbers below are printed pages; PDF indices include front matter. The copyrighted book is not redistributed. This package implements the agreed method families, not all applications or every variant named in the book.

Runnable profiles, mechanism tests and reproducible examples are mapped below. Tests establish their specific assertions; operation and comparative performance require separate runs. Historical raw evaluation data is retained locally and is not distributed. Generate fresh results with the linked scripts and examples, retaining numerical losses as well as gains. NEAT/CPPN/HyperNEAT use the corrected `paper-profile-v2`; checkpoints from the previous profile remain explicitly legacy. Cooperative champion retention was also corrected and re-evaluated.

## Composition boundary

All required families are executable profiles. They are not a Cartesian product of every representation and optimizer. The exact target compatibility matrix is `src/neuroevolution_lab/compatibility.py`; `validate` rejects unsupported combinations. A new combination must define which state is evolved, learned, reset, archived and passed to offspring, and must pass its own mechanism and replay checks before being claimed.

The optional torch execution backend preserves these method identities while batching supported numerical work on CPU/CUDA/MPS. Canonical NEAT evolution remains the same; its phenotype evaluation is tensorized. Device capability, precision differences and hardware verification scope are documented in [accelerator execution](accelerators.md). GPU availability does not expand the supported task or method-composition matrix.

Examples of intentional supported combinations are neural CPPN topology evolution → HyperNEAT phenotype evaluation, architecture evolution → inner gradient training, ERL population → shared replay → gradient actor reinsertion, DQD Jacobians → archive proposals, environment coevolution → ES → cross-environment transfers, and LLM workflow → evolved neural tool gate. NEAT-inspired workflow speciation is not implemented or silently substituted for neural NEAT.

## Primary method sources

- [NEAT](https://doi.org/10.1162/106365602320169811), [CPPN](https://doi.org/10.1007/s10710-007-9028-8), [HyperNEAT](https://doi.org/10.1162/artl.2009.15.2.15202).
- [Novelty search](https://doi.org/10.1162/EVCO_a_00025), [NSLC](https://doi.org/10.1145/2001576.2001607), [MAP-Elites](https://arxiv.org/abs/1504.04909).
- [ES for reinforcement learning](https://arxiv.org/abs/1703.03864), [ERL: shared experience and actor reinsertion](https://arxiv.org/abs/1805.07917), [Differentiable QD](https://arxiv.org/abs/2106.03894).
- [POET](https://arxiv.org/abs/1901.01753), [Evolution through Large Models](https://arxiv.org/abs/2206.08896), [Evolutionary model merging](https://arxiv.org/abs/2403.13187).

These sources define mechanisms and motivate local variants. Empirical claims require recorded results from the relevant implementation and conditions; they cannot be inferred from the papers' reported outcomes or from the existence of these examples.
